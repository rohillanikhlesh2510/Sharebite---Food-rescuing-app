## 🚨 1. Security Policy & Responsible Disclosure

Sharebite is committed to safeguarding the data of donors, non-profit organizations, volunteer delivery riders, and vulnerable community beneficiaries. We appreciate the work of independent security researchers and adhere to standard **Responsible Vulnerability Disclosure** protocols.

### Service Level Agreements (SLA) for Security Reports
- **Initial Triage & Acknowledgment**: Within **24 hours** of report receipt.
- **Vulnerability Assessment & Severity Rating (CVSS v3.1)**: Within **48 hours**.
- **Patch Deployment (Critical / High)**: Within **7 calendar days**.
- **Public Disclosure / Advisory**: Following mutual agreement once patches are live.

## 🔑 3. Authentication & Session Security (GoTrue JWT)

1. **Token Standard**: All authenticated operations utilize cryptographically signed **JSON Web Tokens (JWT)** generated by Supabase GoTrue:
   - Signed with asymmetric **RS256** or symmetric **HS256** keys.
   - Tokens contain user UUID (`sub`), email, and immutable system timestamps (`iat`, `exp`).
2. **Role Tampering Defense**:
   - The user's role is stored in `public.profiles.role`.
   - Clients **cannot** elevate their own role by altering HTTP headers or JWT payloads; role updates require explicit database admin privileges or validated triggers.
3. **Session Lifecycle & Storage**:
   - Tokens are refreshed automatically in the background via Supabase client token refresh events (`onAuthStateChange`).
   - Logout triggers immediate client-side token disposal and invalidates persistent refresh grants on the auth server.

## 🛡️ 4. Row-Level Security (RLS) Threat Matrix

Row-Level Security is strictly enabled on **every database table**. Even if an attacker gains arbitrary REST API access, queries are filtered at the SQL engine level:

| Table | Protected Operation | RLS Policy Rule | Threat Prevented |
|:---|:---:|:---|:---|
| `profiles` | `UPDATE` | `auth.uid() = id` | Prevents User A from editing User B's profile, phone number, or verified status. |
| `food_listings` | `UPDATE` / `DELETE` | `auth.uid() = donor_id` | Prevents unauthorized actors from cancelling or altering another restaurant's donation. |
| `reservations` | `SELECT` | `auth.uid() = user_id OR auth.uid() IN (SELECT donor_id FROM food_listings WHERE id = food_listing_id)` | Prevents external scraping of which shelters are claiming food. |
| `deliveries` | `UPDATE` | `auth.uid() IN (SELECT user_id FROM riders WHERE id = rider_id) OR auth.uid() = donor_id OR auth.uid() = receiver_id` | Prevents unauthorized riders from tampering with delivery status or codes. |
| `messages` | `SELECT` / `INSERT` | `auth.uid() IN (SELECT user_id FROM conversation_participants WHERE conversation_id = messages.conversation_id)` | Eavesdropping protection; only designated chat members can read/post messages. |
| `notifications` | `SELECT` / `UPDATE` | `auth.uid() = user_id` | Prevents cross-tenant notification leaks. |

## 🇮🇳 5. Indian Regulatory & Privacy Compliance (DPDP Act 2023)

Sharebite is designed to comply with India's **Digital Personal Data Protection Act, 2023 (DPDPA)**:

```
┌────────────────────────────────────────────────────────────────────────┐
│                   DPDP ACT 2023 COMPLIANCE PILLARS                     │
├─────────────────────┬────────────────────┬─────────────────────────────┤
│  PURPOSE LIMITATION │  CONSENT NOTICES   │  RIGHT TO ERASURE (FORGET)  │
│ Coordinates captured│ Explicit checkbox  │ Automated user deletion     │
│ only for active trip│ on onboarding forms│ cascading to all sub-tables │
└─────────────────────┴────────────────────┴─────────────────────────────┘
```

### 5.1 Grounds for Processing & Purpose Limitation
- **Location Telemetry**: Rider coordinates (`rider_location_updates`) are captured **strictly** while a delivery task is in `GOING_TO_PICKUP` or `IN_TRANSIT` status.
- **Location Data Expiry**: Inactive rider GPS trails are ephemeral and purged on a scheduled basis, retaining only aggregate trip distances.

### 5.2 Protection of Vulnerable Beneficiaries
- Exact street addresses of children orphanages and women's crisis shelters are **never exposed publicly** on the unauthenticated landing map.
- Coordinates are revealed only to the assigned, verified rider once a claim has achieved `RIDER_ASSIGNED` status.

### 5.3 Data Principal Rights
- **Right to Access & Correction**: Users can view and update their full demographic record directly from `src/pages/app/ProfilePage.tsx`.
- **Right to Erasure (Account Deletion)**: Foreign keys linking `auth.users` to `public.profiles` apply `ON DELETE CASCADE`, ensuring that an account deletion request completely purges demographic records.

## 🍲 6. FSSAI Food Safety & Chain-of-Custody Compliance

To uphold the guidelines of the **Food Safety and Standards Authority of India (FSSAI)** regarding surplus food distribution:

1. **Mandatory Safety Declaration**:
   - Donors must affirm a legal declaration before submitting listings: *"I certify that this food was prepared under hygienic conditions, has been maintained within safe temperature thresholds, and is fit for human consumption."*
2. **Perishability & Shelf-Life Timeouts**:
   - Listings enforce database constraint checks: `CHECK (available_until > available_from)`.
   - The moment `available_until` is reached, database triggers or client queries transition the status to `expired`, automatically pulling it from public discovery.
3. **Receipt Quality & Dispute Logging**:
   - When food arrives at an NGO, the receiver must complete a digital receipt condition checklist.
   - Flagging `safetyConcern = true` immediately escalates the batch to the `food_moderation` queue and freezes the donor's rating for review.
4. **Allergen Declarations**:
   - Explicit tagging for common allergens (Dairy, Gluten, Peanuts, Mustard, Soy) stored as structured arrays in `food_listings`.

## 🔒 7. Cryptographic Standards & Edge Function Security

### 7.1 Image Binary Magic-Byte Validation
Attackers often disguise malicious payloads or scripts with fake extensions (`exploit.jpg`). The `moderate-image` Edge Function inspects the first 12 raw bytes:

```typescript
// Magic byte verification in Deno runtime
const isJpeg = imageBytes[0] === 0xFF && imageBytes[1] === 0xD8;
const isPng  = imageBytes[0] === 0x89 && imageBytes[1] === 0x50;
const isWebp = imageBytes.length > 12 && imageBytes[8] === 0x57 && imageBytes[9] === 0x45;

if (!isJpeg && !isPng && !isWebp) {
  return new Response(JSON.stringify({
    decision: 'rejected',
    reason: 'Invalid binary signature. Only genuine JPEG, PNG, and WebP files allowed.'
  }), { status: 200 });
}
```

### 7.2 Zero Credential Leakage Architecture
- Edge function inference keys (`HF_TOKEN`) and database superuser tokens (`SUPABASE_SERVICE_ROLE_KEY`) are stored in encrypted **Supabase Vault Secrets**.
- Client applications only possess the restricted `VITE_SUPABASE_ANON_KEY`, which cannot bypass RLS.

## 🤝 8. Anti-Fraud & Inventory Tampering Defenses

### 8.1 Two-Factor Physical Handover Handshake (6-Character PIN)
To eliminate theft, ghost deliveries, or impersonation of volunteers:
- **Pickup Phase**: The donor's app displays an encrypted, randomly generated 6-character code (e.g. `SB-4921`). The driver must inspect the food and enter this code in their app to unlock `FOOD_COLLECTED` status.
- **Dropoff Phase**: The receiving NGO generates a separate dropoff code (e.g. `SB-9012`). The driver cannot claim delivery completion without entering this code at the physical destination.

```
[ 🏪 Donor App ] ──(Generates "SB-4921")──► [ 🚴 Driver Enters PIN ] ──► Status: COLLECTED
[ 🏢 NGO App ]   ──(Generates "SB-9012")──► [ 🚴 Driver Enters PIN ] ──► Status: DELIVERED
```

### 8.2 Inventory Double-Claim Mutex
- Implements PostgreSQL `SELECT ... FOR UPDATE` explicit row-locking within `reserve_food()` RPC.
- Guaranteed mathematical prevention of negative inventory, even under distributed bot attacks.

### 8.3 Photo Deduplication Engine
- Edge function calculates a 32-character **SHA-256 binary hash** of every photo.
- Any attempt by a fraudulent donor to download photos from social media or reuse old food pictures triggers immediate rejection: *"This image has already been uploaded. Please capture a fresh photo."*

If you discover a security vulnerability, privacy defect, or RLS bypass within Sharebite, please follow these reporting procedures:

### Where to Report
- **Security Contact**: `security@sharebite.org` / `rohillanikhlesh7@gmail.com`
- **Subject Line**: `[SECURITY VULNERABILITY] - Component Name - Brief Description`

### Information to Include
1. Type of vulnerability (e.g., RLS bypass, XSS, CSRF, Token leakage, Insecure Direct Object Reference).
2. Step-by-step reproduction instructions or a minimal Proof of Concept (PoC).
3. Impact assessment: what user data could potentially be compromised.
4. Any potential remediation recommendations.

### Safe Harbor Guarantee
Security researchers conducting good-faith research that adheres to this policy will **not** be subject to legal action or account suspension. Please do not access or tamper with data belonging to other users during testing.
